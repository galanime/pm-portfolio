CASE 01 · PUBLIC REDACTED DEMO

闲鱼 AI 客服 Agent

商家客服自动化 · 产品负责人兼独立开发者 · 2026.03–2026.05

公开脱敏 Demo

VERIFIED OUTCOME

4 家商家真实使用，1 家购买后续迭代服务。

线上 3 家、北京线下 1 家完成真实使用验证。

产品机制与取舍

  • 规则与 SQLite 管理价格、押金、库存等业务事实，大模型只负责受约束的理解与表达。
  • 覆盖自动生成回复、草稿填入、库存与日历更新；发送机制从人工审核逐步演进到双门禁约束的自动发送。
  • 核心取舍是提升响应效率，同时避免模型误承诺价格、档期与交易条件。

EVIDENCE BOUNDARY

本次公开页不连接真实账号、Cookie、ADB 或外部日历；截图证明受约束客服工作流，不证明真实消息桥接与线上自动发送。

CASE 03 · DETERMINISTIC DEMO

CareerPilot

求职决策 Agent · 工具调用、Provider 切换与可追踪产物

确定性演示

PRODUCT SURFACE

8 个工具 · 4 路 Provider · Trace 与 Artifacts。

把求职判断从单轮对话变成可复核流程。

Agent 产品闭环

  • 通过 JSON Schema 注册工具，让岗位解析、候选人事实、匹配判断与材料输出进入统一运行时。
  • 保留 Provider 切换、失败降级、Trace 回放与产物归档，支持复核结果从哪里产生。
  • 演示侧优先保证确定性和可解释性，不把一次模型输出包装成招聘结论。

EVIDENCE BOUNDARY

百度 JD 仅作为本地演示输入；Fake Provider、95/100 与 100% 只属于该固定样本，不代表百度官方评分或真实招聘判断。
