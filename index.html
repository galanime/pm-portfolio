01. 我怎么做 AI 产品

从用户痛点出发，而不是从技术出发。每个案例我都先回答"用户是谁、卡在哪、为什么现有方案不行"，再设计 AI 工作流去解决它。

把 AI 黑盒变成可解释的流程。我设计的系统都有明确的"感知 → 决策 → 人工卡点 → 执行 → 反馈"链路，让非技术干系人也能看懂 AI 在做什么、为什么这么做。

用数据和指标驱动迭代。我为每个产品定义核心体验指标（完成率、重试率、时延、人工介入率），并搭建评估面板持续验证。

能自己动手验证。我不是只会写 PRD 的 PM——我能用 Python / React 把产品 Demo 跑起来，0 成本验证可行性，再决定要不要投入研发。

02. 产品案例

AI 短视频创作工具

让中小商家"填个表单"就能产出短视频脚本与发布包

痛点

中小商家想做短视频获客，但不会写脚本、不懂剪辑，外包一条成本高、周期长，导致大量商家放弃视频渠道。

我的方案

把短视频生产拆解为 brief → 脚本 → 分镜 → 发布包 的标准化工作流，每一步都是可配置、可预览、可回退的节点；用多智能体分别负责文案、视觉与结构，把"懂剪辑"的门槛降到"填表单"。

关键设计决策

  • ➤ 质量门禁：引入 Prompt 质量评分 + 人工审批前置，避免 AI 生成低质/违规内容直接流出
  • ➤ 双版本策略：Lite 版用于 0 成本演示与获客，Pro 版面向付费商用，能力边界清晰
  • ➤ 降级与成本控制：Mock Provider + 降级链路，无付费 API 也能完整跑通，验证期 0 成本

验证与成果

独立完成可交互 Demo 并跑通完整链路，沉淀界面教程与 Prompt 知识库作为可交付资料；用 29 个自动化测试保证迭代不回退。

AI 运营助手（人机协同）

让自媒体运营"回复不熬夜、话术不踩雷"

痛点

自媒体账号私信/评论量大，人工回复不及时导致粉丝流失；但全自动回复又容易触发平台风控或话术违规，账号风险高。

我的方案

设计 感知 → 分诊 → 拟人化改写 → 人工审批 → 执行 → 学习同步 的人机协同流程：低风险常规问题自动处理，高风险/引流类话术强制进入人工卡点，兼顾效率与账号安全。

关键设计决策

  • ➤ 风险前置拦截：规则引擎先行分诊，高风险动作一律人工确认，把"会不会封号"的不确定性收敛掉
  • ➤ 可解释性：每条自动回复都带决策 route trace，可解释、可回放、可审计，满足平台合规
  • ➤ 运营可自维护：话术库（Notion）与策略解耦，非技术运营同学也能自己维护规则，降低协作成本

验证与成果

用待审队列 + 审计日志的 Web 面板承载运营日常，形成完整人机协同闭环；10 个自动化测试覆盖核心分诊与风控逻辑。

  • 人机协同
  • 风控设计
  • 审批闭环
  • 可解释性

AI 生活助手

回答"AI 助手到底帮没帮上忙"——用指标定义好体验

痛点

很多 AI 助手"看起来能聊，实际上办不成事"，用户说不清它哪里不好，团队也无法判断该优化哪里——缺少一套可量化的体验评估方法。

我的方案

设计 意图识别 → 任务拆解 → 工具调用 → 结果聚合 的完整用户旅程，并定义完成率、重试率、端到端时延、人工评分等核心体验指标，把"好不好用"变成可测量的数据。

关键设计决策

  • ➤ 核心指标定义：以"任务是否真正完成"为北极星，而非"是否回复了用户"
  • ➤ 评估面板：搭建评估仪表盘 + 人工评分入口，用数据驱动迭代意图识别与工具选择策略
  • ➤ 过程可视化：任务 DAG + Trace + 会话回放，让非技术干系人看懂 AI 决策链路，降低验收成本

验证与成果

105 个自动化测试保障体验不回退；评估体系可直接迁移到任何"AI 助手/Agent"类产品的体验度量。

  • 核心指标
  • 评估体系
  • 数据分析
  • AI Agent
  • 体验设计

考研题库学习产品

微信小程序刷题 + 答疑工单的多角色流程设计

痛点

考研学生在碎片时间刷题需求强，但传统题库产品重、答疑链路长，学生提问后得不到及时反馈，学习闭环断裂。

我的方案

设计 学员刷题 / 教师答疑 / 管理员工单 三角色闭环：学员端刷题 + 错题 + 讨论 + 模拟考试，教师端答疑工作台，管理员工单升级与分配，用小程序承载轻量化学习场景。

关键设计决策

  • ➤ 多角色流程：12 个页面打通三类角色，答疑可升级、可追踪，形成完整学习服务闭环
  • ➤ 轻量化验证：本地数据驱动，无需后端即可演示完整流程，快速验证产品逻辑
  • 多角色流程
  • 教育产品
  • 小程序
  • 学习闭环
